## Top 3 findings

1. **Test runs are unfiltered, but tests are not over-produced.** Over 60 days sessions added 587 test functions against 41,507 production lines (1.41 per 100). 557 of 1,029 Gradle test runs had no filter and 281 ran the whole project. One orchestrated session with parallel writer subagents made most of the whole-project runs.
2. **Subagents find the guard rules by trial and error.** Over 60 days a worktree-isolation guard blocked 246 calls and other hooks blocked 83. `sleep` ran 281 times and 130 of those were polling loops. The briefs did not state the limits.
3. **Shell commands replace the file tools.** Over 60 days 6,958 Bash calls led with `grep`, `sed`, `cat`, `head`, `tail`, `awk` or `rg`, which is 17.9% of all tool calls. The share fell to 7.9% in the last 14 days. Bash is 66% of all tool calls.

## Writing-style rules

The rules hold. Over 60 days replies carry 0.18 dashes and 0.26 semicolons per 1,000 words, against about 23 and 6 before the rules. A model change landed 8 days before the rules first loaded, so the rules' own share of that drop is not proven. The bold rule is not followed: 65% of replies contain bold. The per-prompt hook has no measured effect of its own, which is why the hook experiment is in the backlog.

## Changes applied with this baseline

- `shared/guidance/design-standards.md` now loads only for UI files, which removes 13,550 characters from every other session.
- The Android, iOS and web test rules and the orchestrate skill now say to run filtered tests while iterating and the module or full suite once.
- The subagent brief in `shared/guidance/common.md` now states the guard limits and the preferred file tools.
- The style hook says "numerals from 2 up", which matches the rule.
- Local only: 8 redundant or broad permission rules removed, including one that allowed any `git branch` command, one dead skill override removed, and one project's memory index trimmed from 23,406 to 8,665 bytes with the detail moved into the memory files.
